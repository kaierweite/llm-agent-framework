# 需求文档：LLM Agent Framework → 企业知识库问答系统

> 版本：1.0  
> 日期：2026-05-06  
> 状态：初稿

---

## 1. 项目背景

### 1.1 现有系统

当前项目是一个基于命令行的 LLM Agent 框架（`llm-agent-framework`），具备以下能力：

| 能力 | 实现模块 | 现状 |
|------|---------|------|
| LLM 对话（流式输出） | `llm/client.py` | ✅ 已实现 |
| 工具调用（文件操作、网络请求、天气） | `tools/file_tools.py`、`tools/network_tools.py` | ✅ 已实现 |
| 技能系统（SKILL.md 加载） | `tools/skill_tools.py` | ✅ 已实现 |
| AnythingLLM 知识库查询 | `tools/network_tools.py` | ✅ 已实现 |
| 对话历史管理与自动压缩 | `core/history.py` | ✅ 已实现 |
| JSONL 日志系统 | `logging/logger.py` | ✅ 已实现 |

### 1.2 目标产品

将现有 CLI 工具改造为 **企业知识库问答系统**（Web 服务），支持：

- 多用户通过浏览器访问
- 企业文档上传、向量化、检索问答
- 管理后台（用户管理、知识库管理、技能管理）
- 私有化部署（Docker 一键启动）

---

## 2. 用户角色

| 角色 | 说明 | 核心需求 |
|------|------|---------|
| **管理员** | 企业 IT 管理员 | 管理用户、配置知识库、管理系统设置、查看使用统计 |
| **普通用户** | 企业员工 | 登录系统、选择知识库提问、查看历史对话 |
| **访客**（可选） | 未登录用户 | 只能使用通用问答，不能访问企业知识库 |

## 4. 非功能需求

### 4.1 性能

| 指标 | 要求 |
|------|------|
| 并发用户数 | ≥ 50 人同时在线 |
| 首次响应时间 | < 2 秒（不含 LLM 生成时间） |
| 流式输出延迟 | 首 Token < 1 秒 |
| 文档上传大小 | 单文件 ≤ 50MB |
| 文档向量化时间 | 单文档 < 5 分钟 |

### 4.2 安全

| 要求 | 说明 |
|------|------|
| 密码加密 | bcrypt 哈希存储 |
| Token 认证 | JWT，支持过期和刷新 |
| 文件上传校验 | 校验文件类型、大小，防恶意文件 |
| 路径遍历防护 | 沿用现有 `_validate_path` 机制 |
| SSRF 防护 | 沿用现有 `_is_safe_url` 机制 |
| CORS 配置 | 仅允许指定域名访问 |

### 4.3 可用性

| 要求 | 说明 |
|------|------|
| 浏览器兼容 | Chrome 90+、Firefox 88+、Edge 90+、Safari 14+ |
| 响应式布局 | 支持桌面端和移动端 |
| 深色模式 | 提供深色/浅色主题切换 |

### 4.4 部署

| 要求 | 说明 |
|------|------|
| Docker 部署 | 提供 Dockerfile 和 docker-compose.yml |
| 一键启动 | `docker-compose up -d` 即可运行 |
| 配置文件 | 环境变量配置，支持 `.env` 文件 |
| 数据持久化 | 数据库、上传文件、日志持久化到宿主机 |

## 5. 现有代码改动范围

### 5.1 保留不动

| 模块 | 原因 |
|------|------|
| `llm/client.py` | LLM 调用逻辑通用，无需改动 |
| `tools/file_tools.py` | 文件操作工具，Web 端仍可复用 |
| `tools/network_tools.py` | 天气、网络请求工具，Web 端仍可复用 |
| `tools/skill_tools.py` | 技能加载逻辑，Web 端仍可复用 |
| `core/prompts.py` | 系统提示词生成，Web 端仍可复用 |

### 5.2 需要改造

| 模块 | 改动内容 |
|------|---------|
| `cli.py` | **废弃**，替换为 FastAPI 入口 |
| `core/agent.py` | 去掉 CLI 相关代码，保留核心编排逻辑，改为可被 API 调用的 Service 层 |
| `core/history.py` | 改为从数据库读写对话历史，不再内存存储 |
| `logging/logger.py` | 保留文件日志，同时增加数据库日志记录 |

### 5.3 需要新增

| 模块 | 说明 |
|------|------|
| `api/` | FastAPI 路由层（对话、用户、知识库、管理） |
| `models/` | 数据库模型（User、Conversation、Message、KnowledgeBase、Document） |
| `services/` | 业务逻辑层（AuthService、ChatService、KnowledgeService） |
| `middleware/` | 中间件（认证、CORS、限流） |
| `config.py` | 统一配置管理 |
| `database.py` | 数据库连接管理 |

## 7. 约束与假设

### 约束

1. 后端语言仍使用 Python，保持与现有代码一致
2. 不引入前端框架的构建复杂度，优先使用成熟的 Vue 3 + Element Plus
3. 知识库向量化依赖 AnythingLLM，不自建向量数据库（MVP 阶段）
4. MVP 阶段不实现 WebSocket，使用 SSE 实现流式输出

### 假设

1. AnythingLLM 已部署并可正常访问（`localhost:3001`）
2. LLM 服务已部署并可正常访问（`localhost:1234`）
3. 目标部署环境为 Linux 服务器（Docker）
4. 企业内网环境，无需考虑高并发（< 100 人同时在线）
